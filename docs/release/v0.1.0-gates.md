## Definition of Done (stories US-001 to US-013)

All stories are closed with AC evidence in their issues and in [implementation status](../implementation-status.md). Each one meets these conditions:

- TypeScript strict checks pass;
- unit tests and the required integration tests pass;
- automated accessibility has no regressions;
- no new permissions, and no LinkedIn scraping or automation;
- error states are handled;
- documentation is updated.

Two caveats. "Code is reviewed" has meant self-review only, so an independent review is recommended before release. "Works in supported browsers" is verified only for Chrome and Edge 156 on Windows.

## Pilot measurement plan (PRD section 2)

The pilot uses no analytics SDK and transmits no drafts. Participants join by informed consent and report through a form they fill in themselves. The targets below are goals, not results; results are recorded separately when the pilot runs.

**Participants:** 10–20 people who publish on LinkedIn at least monthly. They are recruited directly and may withdraw at any time. Each gets a short consent note covering what is asked, that no drafts or post content are collected, how long answers are kept (until the v0.2 decision, at most 6 months), and who sees them (the PostNook owner only).

**Method:** participants install the store build or an unpacked build. At day 1, week 1 and week 4 they answer a 2-minute self-report form: yes/no questions, counts and a 0–10 score, with no free-text draft content. Recovery and copy/paste are measured in a controlled session, not through usage tracking.

| KPI                        | Target        | How it is measured                                                    |
| -------------------------- | ------------- | --------------------------------------------------------------------- |
| First-post activation      | 60%           | Day 1: "Did you write and copy a post with PostNook?"                 |
| Successful copy/paste      | 95%           | Controlled QA-005 sessions: cases pasted without blocking differences |
| Draft recovery             | 100% of tests | QA-002 and automated recovery tests                                   |
| Second-post creation       | 40%           | Week 1: "Have you started a second post in PostNook?"                 |
| Week-4 retention           | 25%           | Week 4: "Did you use PostNook for a post in the last 7 days?"         |
| Pilot satisfaction         | 8/10          | Week 4: "How likely are you to keep using PostNook?" (0–10)           |
| Critical data-loss defects | 0 unresolved  | Defects reported by participants and QA, in GitHub issues             |

**Results:** not started; record them here with the date and sample size when the pilot ends. Post-MVP features (PRD section 20) stay deferred until week-4 retention shows recurring use.

## Before tagging v0.1.0

1. Close QA-002 (macOS Chrome at least), QA-004 (human keyboard and screen-reader runs) and QA-005 (manual LinkedIn paste), fixing any blocking finding.
2. Push, confirm CI passes on GitHub, and make the CI job a required check for `main` (repository settings).
3. Have an independent code review.
4. Tag `v0.1.0`, verify the draft release, then submit to the stores ([store submission](store-submission.md)).
